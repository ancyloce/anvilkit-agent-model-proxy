# anvilkit-agent-model-proxy

The Model Proxy of the AnvilKit Agent platform: the sole runtime holder of model provider credentials and the only model exit (DD-03 §2 ControlledModelPort and §6 model stream, B05 pi-ai, `security.md` credential isolation). It serves the frozen transport `openapi/model-proxy.yaml` of the contracts repository (`POST /api/v1/model-calls` with Server-Sent Events, `GET /api/v1/model-calls/{callId}`, `POST /api/v1/model-calls/{callId}/cancellations`) to the Workflow's fixed Go Activities and to the trusted access sidecar of a Job. Every physical send needs its own single-use `AdmitModel` permission from Control, goes through one guarded transport with transparent retries, fallback and redirects disabled, is normalized into the bounded `StreamFrame` sequence, and leaves private native evidence and an idempotent `ObserveDispatch` observation behind. Control remains authoritative for admission, budgets, billing and recovery; this service owns controlled sending, protocol adaptation, native evidence and usage observations. The architecture that owns it is the parent repository `anvilkit-services` (`docs/architecture/execution.md` DD-02 §4 and DD-03 §2/§6, `contracts.md` §1 and §4, `delivery.md` P11); the parent mounts this repository as the submodule `services/agent/model-proxy`.

The generated contract consumers (`@anvilkit/generated-clients`, `ts/` of the contracts repository) are a git-hosted dependency pinned by commit and content integrity in `pnpm-lock.yaml` (`github:ancyloce/anvilkit-agent-contracts#1e7cb5d…&path:ts`, the TypeScript analogue of a Go pseudo-version; `.github/workflows/ci.yml` checks the same commit out and the `Dockerfile` accepts the contract document at that commit's digest only); nothing is read from a sibling checkout except the contract document itself, which the environment (or the image's named build context) names.

## What the Proxy guarantees, and how it is checked

- **Single physical send.** A call is sent only by the request Control told `dispatchAllowed=true`; a lost first answer, a duplicate on another instance, a reentry, a retryable SDK error, a connection failure, a redirect, a restart or a query never sends again. The pinned SDK (`@earendil-works/pi-ai` 0.85.1, the current name of pi-ai) was inspected: its `openai-completions` path (`api/openai-completions.js`) builds one vendor client per call on the `fetch` the request option names (`ProviderRequestOptions.fetch`, handed to `new OpenAI({ fetch })`), calls the vendor SDK with `maxRetries: 0` and wraps it in its own retry helper that retries nothing at `maxRetries: 0`, and has no fallback; the Proxy calls that path directly (no registry dispatch, no `streamSimple`), passes `maxRetries: 0`, the deadline-bounded timeout, the abort signal, `cacheRetention: "none"` and the fetch of the call's ticket. The ticket's fetch allows one request, the route's origin and path only, exactly the route credential as `Authorization`, no forwarded caller header, and never follows a redirect (`redirect: "manual"`; a 3xx is a failed send); the process-wide fetch is replaced at bootstrap by one that refuses, so nothing in the process sends without a ticket. `test/transport.test.ts` proves it on the real SDK path against a countable upstream (500/429/503, dropped connection, hang, abort, redirect: one receive each, no refused retries).
- **Reentry, not resend — for the call's own caller.** The record of a call is read before anything else: the same call id with the same immutable content (the caller's `requestDigest` and the content digest the Proxy computes) replays the recorded frames or attaches to the live send; changed content is `IDEMPOTENCY_CONFLICT`; a call whose permission was consumed elsewhere waits for that record. A call's identity is Control's dispatch identity — the tenant of the binding and the call id — so the same call id under two tenants is two calls, each with its own admission, send, record, evidence, marker and cancel intent, and a record is only ever taken over (the permission holder over the `PERMISSION_LOST` placeholder a duplicate recorded under the same caller, digests and dispatch), attached to or settled by the identity it was recorded for; nothing under a scope is overwritten. A call is reentered, queried and canceled by the principal that opened it (any replica of that workload: the same identity); a query is also answered to a principal of kind `control` (Control's recovery query of the original identity); any other identity — however valid its token or certificate, whatever call id it names — is answered `NOT_FOUND` on a query or a cancel and `FORBIDDEN` on a reentry, and nothing changes. A query or a cancel names the call by id alone (the transport carries no tenant there): it is answered the one record of that id the caller may see; a caller whose calls of several tenants share an id is answered `NOT_FOUND` rather than one of them (the binding of a reentry still names each).
- **The tool round trip.** A `tool_call` frame carries the call id, the name and the arguments (JSON object text) with their digest; the next request replays them as the assistant message's `toolCalls` and answers each with a `tool` message naming the call (`Message` of the contract). The Proxy validates the round trip (tool calls only on assistant messages, of reviewed tools, with JSON-object arguments and distinct ids; a tool message answers exactly one earlier call) and pi-ai serializes it as the protocol's `tool_calls` and `tool` messages; the Proxy executes no tool and runs no agent loop, and each request is its own admission.
- **Bounded frames.** Sequence 0 is `admitted`; the route's `max_frame_bytes` bounds the encoded UTF-8 size of every content frame (text is split there and at the contract's 65536-byte text bound without breaking a code point; a tool call is one frame within it and the contract's 262144-byte argument bound, else `FRAME_BOUND_EXCEEDED`); `max_output_bytes` bounds the UTF-8 content of one call (`OUTPUT_BOUND_EXCEEDED`); `max_frames` bounds the count with its last slot reserved for the final frame (`SEQUENCE_BOUND_EXCEEDED` when content would need it), so the outcome of a bound hit always reaches the caller and the record; the final frame is `done` or `error` once and is bounded by the contract, never by the route; every frame is checked against the contract before it is written, and a frame outside it cuts the stream instead of hiding a gap.
- **Native evidence, then the settlement.** The request as sent (without the credential), the raw response and the settlement they establish (outcome, usage, native reference, frames) are persisted once per call under `evidence/<callId>/<tenantId>`, then the pending marker is written again (a sweep that reclaimed the send meanwhile may have released it), then the record takes the settlement under a conditional write (a record moved by a concurrent cancel or by another instance is reloaded and the settlement reapplied, never dropped), then the observation is offered to Control — before the caller receives the final frame; while the store does not take the settlement, the callers wait and it is retried. Usage is the native counters the stream carried (`prompt_tokens`, `completion_tokens`, cached and reasoning details as reported by the `openai-completions` protocol), never pi-ai's normalized or priced figures: Control's price book interprets inclusion (DD-02 §3). A stream without a usage chunk is `unknown` (`USAGE_MISSING`); a usage object outside the protocol — an empty object, a missing, negative, fractional or non-numeric required counter, a `total_tokens` that is not the sum, a detail that is not an object or a cached/reasoning count above its parent — is `unknown` (`USAGE_INVALID`) with no counters reported and the exposure retained; complete counters settle, explicit zero included; absent optional details count as zero.
- **Cancellation is intent.** A cancel is recorded durably and aborts a send this process owns, or one on another instance through the store; incurred usage stays; a cancel before the first byte leaves the process settles as canceled with explicit zero usage (a certain fact of the sender), a cancel after it as canceled with the native usage or unknown without it; a cancel that lands during the settlement neither loses the outcome nor the usage.
- **Process loss and recovery.** The pending marker (with the call's deadline) is written before the record, so any instance's sweep discovers a call however early its opener died (an orphan marker is cleared only after the deadline plus grace); a send is recorded with its dispatch identity before any byte leaves. A record still `sending` whose evidence carries a settlement is completed from it by any instance's sweep — the original outcome, usage and frames, one supplemental observation, no send; a record still `sending` past its deadline plus grace without evidence is reclaimed as `unknown` (`SENDER_LOST`) and observed as unknown — never as sent-nothing, never resent — and its pending marker stays for `observation.late_settlement_window` after the reclaim (`reclaimedAt` on the record): evidence the lost sender persisted after the reclaim, its process gone before the record took it, is completed from by any instance's sweep — the original settlement and usage under the original dispatch, one supplemental observation, no send — and a sender still alive supersedes the reclaim itself when its settlement establishes more (a definite outcome or usage). Evidence settles only the dispatch it was made under. A marker is released once nothing more can arrive: the record is settled from its evidence (evidence is written once), was denied or lost its permission, or the late-settlement window passed. Pending observations are resubmitted under their recorded source and sequence (`model-proxy/<instance>`), so a lost `ObserveDispatch` answer is retried without double charge, and Control charges the same cumulative usage once whichever source reports it.
- **Never in the open.** Native bodies, provider credentials and caller tokens never enter the SSE, the records' public view or the logs (controlled identifiers, states, codes, counts and durations only).

## Configuration

One reviewed, secret-free file (`config.yaml`, path from `ANVILKIT_MODEL_PROXY_CONFIG`) with the sections `http`, `health` (the probe listener, `listen`, default `127.0.0.1:9104`: plaintext, `/healthz` and `/readyz` only, no identity — the kubelet presents no client certificate, so the probes never share the mTLS business listener), `identity` (`disabled`, `development` with a bearer principals file, or `mtls` with the workload certificate files and the common names of the callers), `control` (address, timeout, identity mode, admission reentry bounds), `store` (`filesystem` DEVELOPMENT_ONLY or `s3`), `observation` (resubmission backoff, `sweep_interval`, `reclaim_grace`, `late_settlement_window`) and `routes`. A route names its `api` (only `openai-completions` is implemented and inspected in this build), the trusted `provider`/`model` Control's price observation binds, its `base_url`, the environment variable of its credential (`credential_env`, `ANVILKIT_MODEL_PROXY_CREDENTIAL_<NAME>`), its limits (output tokens, exposure bound and currency, deadline, the encoded frame bound `max_frame_bytes` in `[1024, 4194304]`, the output bound `max_output_bytes`, the frame count `max_frames`, upstream timeout, evidence bound) and its reviewed tool schemas; callers name a tool by the sha256 of its canonical schema. The only environment overrides are `ANVILKIT_MODEL_PROXY_LISTEN`, `ANVILKIT_MODEL_PROXY_HEALTH_LISTEN`, `ANVILKIT_MODEL_PROXY_CONTROL_ADDRESS`, `ANVILKIT_MODEL_PROXY_PRINCIPALS_FILE`, `ANVILKIT_MODEL_PROXY_STORE_DIR`, `ANVILKIT_MODEL_PROXY_STORE_S3_{ENDPOINT,BUCKET,ACCESS_KEY_ID,SECRET_ACCESS_KEY}`, `ANVILKIT_MODEL_PROXY_CONTRACTS_DIR` and the declared route credentials; any other `ANVILKIT_MODEL_PROXY_*` variable stops the process. The checked-in file declares the controlled route `controlled-openai-v1` (an OpenAI-compatible completions double, provider `fixture`, model `fixture-model`) with `enabled: false`; the verification scenarios enable it in their own copies. No real provider route exists: declaring one needs explicit model, data, price, cap and invocation authorization (ENV-06), and the routes' commercial authority stays with Control.

Deadlines are stated at millisecond precision (the transport's `Timestamp` at the precision the admission carries); the Go callers format them so.

## Build and verify from this repository alone

```sh
pnpm install --frozen-lockfile --ignore-scripts   # Node.js 24, pnpm 12.3.4; no lifecycle script runs (pnpm-workspace.yaml)
pnpm run check-types && pnpm run lint && pnpm run build
ANVILKIT_MODEL_PROXY_CONTRACTS_DIR=<contracts checkout> pnpm run test   # the contract document and its vectors; beside the parent checkout it is found automatically
docker build --build-context contracts=<contracts checkout> -t anvilkit-agent-model-proxy:dev .
helm lint deploy/chart --set control.address=anvilkit-agent-control:9101 --set store.s3.endpoint=http://minio:9000 \
  --set store.s3.bucket=anvilkit-model-proxy --set store.s3.secret.name=model-proxy-store --set identity.principalsSecret.name=model-proxy-principals
```

The tests run against an in-process countable upstream double (its events encoded by `eventsource-encoder`, read back with `eventsource-parser`) and a fake Control (grpc-js) with the filesystem store; `test/store.test.ts` also exercises the S3 backend when `ANVILKIT_DEV_ARTIFACTS_ENDPOINT` and `ANVILKIT_DEV_MODEL_PROXY_{BUCKET,ACCESS_KEY_ID,SECRET_ACCESS_KEY}` name a bucket (the parent's development foundation), and `test/mtls.test.ts` generates its certificates with `openssl`. The parent's `tests/integration` runs the same service as two processes against two real Control processes, the Workflow's `CallModel` Activity (the tool round trip included) and the access sidecar, with the receive counts of the upstream and Control's database as the evidence.

The event stream is the SSE protocol as the libraries implement it: `eventsource-encoder` writes the frames (`id` = sequence, `data` = the frame's JSON) and the keepalive comments, `eventsource-parser` reads the captured upstream body; the Go callers read the Proxy's stream with `github.com/tmaxmax/go-sse` (`sse.Read`, no reconnecting client) with an event bound of the route's frame bound plus the field overhead. This service keeps the identity, sequence, cancellation, backpressure, limits and recovery; the libraries keep the protocol.

## Deploy

`deploy/chart` carries only what this service needs. Required values: `control.address`, the shared store `store.s3.{endpoint,bucket,secret.name}` (every replica must use the same backend; the filesystem adapter is DEVELOPMENT_ONLY and is not rendered), `identity.principalsSecret.name` under `identity.mode: development` or `identity.mtlsSecret.name` under `mtls`, and one `routeCredentials` entry per served route (the environment variable the route declares and the existing Secret holding the credential; a route without one stays unserved). The chart never creates Secrets. `image.digest` pins the exact image; `config` renders the reviewed file — routes included — into a ConfigMap; the probes target the plaintext health port (`health.port`, `ANVILKIT_MODEL_PROXY_HEALTH_LISTEN`; `/readyz` for startup and readiness, `/healthz` for liveness) in both identity modes, so mandatory client certificates on the business listener never break them and the Service exposes the business port only; resources, the security context (non-root, read-only root filesystem) and a PodDisruptionBudget are declared. Environment values and the pinned deployment combination belong to the deploying repository (`anvilkit-services`, `deploy/dev` for the development foundation). Plaintext gRPC to Control, the bearer principals and the controlled route are development inputs; runtime qualification (the parent's G gates) and real-provider qualification are not claimed by any check here.
